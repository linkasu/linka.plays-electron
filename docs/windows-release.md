# Windows-релиз с сохранённым лаунчером

Публичный комплект 3.0.0 заменяет Unity на Electron, но сохраняет отдельное
окно «LINKa запуск», ярлыки на него и URL `/linkaplay/linkaplaysetup.exe`.
Требуется Windows 10 1809+ или Windows 11 x64. Данные пользователей и неиспользуемые
файлы Unity автоматически не удаляются; перенос формата настроек Unity не заявляется.

## Упаковка

`resources/electron/installer.iss` использует прежний Inno AppId
`{D17098DB-EAFA-4EFF-A280-65E1CFBAE428}`. Electron устанавливается как
`LINKa.plays.exe`, рядом — self-contained .NET 10/WPF лаунчер и `version.json`.
При обновлении сохраняется предыдущий, в том числе нестандартный, каталог.
Ярлыки ведут на лаунчер; `linka-play://game/<id>` ведёт непосредственно в Electron.
Лаунчер запускает EXE относительно собственного каталога. Проверка обновлений
не блокирует окно и ограничена пятью секундами; без сети игры доступны.

Windows Electron-updater отключён. Версия стабильного комплекта должна быть
числовой и выше предыдущей (Unity: 2.0.0); beta не попадает в публичный манифест.
Тестовые Electron 0.1.x обновляются ручной установкой полного комплекта.

## Кандидат и приёмка

1. Игровая основа 3.0.0 — `e0a590e008ae49885102767d82835a5d5d584933`.
   Зафиксировать итоговый SHA с изменениями доставки. Commit лаунчера закреплён
   в `.github/workflows/release.yml`; исходники доступны в `linkasu/LINKa.plays-launcher`.
2. Запустить `release.yml` на нужном ref с `version=3.0.0`, `publish=false`.
   Это собирает кандидат без публичного релиза и изменения сайта.
3. CI проверяет typecheck, unit, publisher, layout, readiness, TTS, packaged
   privacy/window, затем настоящий Unity setup с закреплённым SHA-256 → новый
   setup в старом каталоге, сохранение файла пользователя/ярлыка/протокола и
   чистую установку. .NET 6 в CI нужен только старому установщику, не новому.
4. На Windows проверить именно этот артефакт: лаунчер, запуск из чужого CWD,
   понятную ошибку при отсутствии игрового EXE без закрытия лаунчера и реальное
   Electron-окно. Проверить PNG, а не только CDP JSON. Игры с Tobii проверяются
   отдельно от CI, который использует `LINKA_NO_TOBII=1`.
5. Установщик не подписан сертификатом разработчика; предупреждение Windows
   не является основанием отключать Defender/UAC.

## Публикация

После приёмки публиковать проверенные артефакты по новому неизменяемому тегу.
Не заменять файлы уже выпущенного GitHub Release. Выпуск публикуется с
`--latest=false`, без NSIS `latest.yml`: старые Electron/macOS-updater не должны
получить несовместимый Windows-комплект. При ручном `publish=true` workflow
заново собирает и проверяет комплект; для публикации уже принятого кандидата
использовать скачанные CI-артефакты без повторной сборки.

`publish-linka-plays-updater.yml` получает точную версию и запускает на сервере
`scripts/publish-windows-release.mjs`. Он проверяет release tag, stable-статус,
имена артефактов, размер и SHA-256 из GitHub; блокирует параллельную публикацию
и понижение версии. Сначала проверяются оба скачанных файла, затем создаётся
резервная копия, атомарно меняются установщики и `launcher.zip`, и лишь затем
оба `version.json`. После сбоя проверить состояние и резервную копию до повтора.

Пути относительно `/home/aacidov/linka-docker/wordpress/`:

- `linkaplay/linkaplaysetup.exe`, `linkaplay/version.json`, `linkaplay/launcher.zip`;
- `dist/linka.plays/linka.plays.setup.exe`, `dist/linka.plays/version.json`;
- `linkaplay/archive/` — предыдущие публичные комплекты;
- `linkaplay/archive/unity-2.0.0-setup.exe` — неизменяемый CI fixture,
  SHA-256 `344b39997ebda4a1cf13211b200f06aaf590149704d341a81cbd4ca5f8593381`.

Перед изменением WordPress сохранить БД. На `/play` убрать только ссылку
Унгуряну (сам EXE оставить), указать Windows 10/11 x64 и сохранённый лаунчер.
Проверить публичные манифесты, SHA-256 обоих URL и скачанный с сайта setup.
При откате новых загрузок восстановить точную резервную копию; уже установленную
3.0.0 исправлять выпуском 3.0.1, не объявлять 2.0.0 её обновлением.
