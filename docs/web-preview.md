# Web Preview

Игры собираются как обычный статический сайт и публикуются на GitHub Pages,
чтобы их можно было открыть по ссылке — без сборки, без установки, без
айтрекера. Это нужно кураторам и дефектологам: сейчас, чтобы посмотреть одну
игру, надо собрать Electron.

- `main` → `https://linkasu.github.io/linka.plays-electron/`
- каждый pull request → `.../preview/pr-<номер>/`

Точка входа для тестировщика — `tests.html`: список всех игр, каждая
открывается по ссылке.

- `.../tests.html` — список игр
- `.../play.html#/games/<id>` — игра в рамке с фиксированным соотношением сторон
- `.../#/games/<id>` — игра во весь экран, без рамки

Ссылка на конкретную игру — это маршрут после решётки:

```
https://linkasu.github.io/linka.plays-electron/#/games/who-hiding
https://linkasu.github.io/linka.plays-electron/preview/pr-12/#/games/number-2048
```

Маршрутизация хэшем и `base: "./"` в `vite.config.ts` уже позволяют жить в
подкаталоге: `resolvePublicAssetUrl` собирает пути к аудио и картинкам
относительно документа, поэтому превью работает без отдельной сборки.

## Что нужно сделать один раз

**Включить Pages может только администратор репозитория.** Settings → Pages →
Source: *Deploy from a branch*, ветка `gh-pages`, папка `/ (root)`. До этого
момента workflow отрабатывает и ветку пишет, но сайт не отдаётся.

## Чего в браузере нет

| | в браузере |
|---|---|
| Айтрекер Tobii | нет, управление мышью |
| Телеметрия и настройки приватности | нет, ничего не отправляется |
| Автообновление | нет |
| Шахматы (`chess-mini`) | не работают: движок нативный, игра честно пишет об этом на экране |
| «Четыре в ряд», шашки, реверси | работают на JS-фолбэке, без нативного движка |
| Остальные 132 игры | работают |

Проверено запуском собранного сайта в Chromium без preload-моста: все маршруты
отрисовываются, ошибок выполнения нет.

### Звук молчит до первого клика

Браузеры не дают воспроизводить звук, пока человек не сделает настоящий клик:
`play()` отклоняется с `NotAllowedError`, `AudioContext` остаётся `suspended`.
В Electron этого ограничения нет.

Это важно именно для ссылок на конкретную игру: человек открывает
`.../#/games/who-hiding`, попадает сразу в игру, задание должно прозвучать — и
не звучит, пока он куда-нибудь не нажмёт. Со стороны это выглядит как «озвучка
не работает», хотя дело в политике браузера.

Пока не сделан экран-заглушка с первым кликом, при отправке ссылки кураторам об
этом стоит предупреждать.

## Фиксированное соотношение сторон

Вёрстка намеренно не адаптивная: она заполняет окно единицами вьюпорта и
рассчитана на окно примерно как у Electron — 1280 × 800. Окно браузера же
такое, каким его растянули, поэтому два тестировщика видят разную геометрию
одной игры и расходятся в том, попадается цель или нет.

`play.html` убирает эту переменную: приложение открывается внутри рамки с
заданным соотношением, рамка вписывается в окно целиком. Соотношение
переключается в верхней панели (16:10, 16:9, 4:3) и запоминается.

Сделано снаружи, а не в приложении: **внутри iframe вьюпорт — это сама рамка**,
поэтому все `vh` в играх продолжают значить то же, что значили, и ни одна из
1047 записей с единицами вьюпорта в 124 файлах не меняется.

Агенту рамка не нужна: `audit:gaze` и `audit:electron-cdp` задают размер окна
сами через CDP.

## Свой домен

Адрес меняется на уровне настроек Pages, не в этом репозитории: Settings →
Pages → Custom domain, плюс CNAME-запись в DNS. Тоже нужен `admin`.

Файл `CNAME` в корне `gh-pages` публикация не трогает — иначе первое же
переиздание корня стёрло бы домен, и Pages молча вернулся бы на адрес по
умолчанию.

## Как устроена публикация

`.github/workflows/web-preview.yml` собирает рендерер и зовёт
`.github/scripts/publish-web-preview.sh`, который переписывает ветку `gh-pages`
**одним orphan-коммитом**, сохраняя чужие превью.

История не ведётся намеренно: одна сборка весит около 67 МБ, из них 30 МБ аудио
и 27 МБ картинок, и растущая ветка оплачивается всеми, кто клонирует
репозиторий. Одинаковые файлы git хранит один раз, поэтому само превью стоит
не 67 МБ, а размера изменившегося бандла.

Превью закрытого pull request удаляет **следующая публикация корня**, а не
событие закрытия. Так сделано после того, как это сломалось на практике: мёрдж
порождает и push в `main`, и закрытие pull request, то есть два force-push в
`gh-pages` с разницей в секунды. Pages начинал собирать первый, второй его
перебивал, и первый отчитывался как «Page build failed». А когда публикаций
набиралось три, очередь Actions выбрасывала ожидающую — и очистка молча
пропадала.

Сверка идёт по списку открытых pull request: всё, чего в нём нет, удаляется.

**Pull request из форка превью не получает:** у него read-only токен. Ветку
нужно заводить в самом репозитории.
